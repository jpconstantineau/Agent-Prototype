Each of the eight documents has the same three official linter warnings, for 24 warnings in total. These are `orphaned-tokens` for **border**, **divider** and **focus**. These colors are consumed by CSS boundaries/outlines, proven by the local custom-property check and browser audit. They are not referenced by the format’s background/text component fields. The warning is retained rather than mislabeling a border as a text/background role or adding unsupported component fields just to silence the tool. Review that tradeoff if the Google component schema gains appropriate boundary/focus properties.

Palette contrast uses measured CSS roles; the simulation tests do not claim clinical equivalence or prove usability for every person. The catalog revision passed the complete 72-test browser suite and all 76 unit tests, including the existing app and content references. All eight Google documents retain zero errors and the documented warning set. Normal/compact desktop forms, compact dark/mobile layout and the compact focused/invalid field were visually inspected. ## Reproduce

From the repository root:

```sh
node UI-Spec/build.mjs --check
node UI-Spec/verify-bootstrap.mjs
cd docs
npm test
npm run test:browser
```

To rerun the separate official format check from docs, with the pinned CLI (downloaded as a development check, not a browser dependency):

```sh
npm exec --yes --package=@google/design.md@0.4.0 -- designmd lint ../UI-Spec/DESIGN.md | node ../UI-Spec/record-design-lint.mjs light-standard
npm exec --yes --package=@google/design.md@0.4.0 -- designmd lint ../UI-Spec/themes/dark.DESIGN.md | node ../UI-Spec/record-design-lint.mjs dark-standard
npm exec --yes --package=@google/design.md@0.4.0 -- designmd lint ../UI-Spec/themes/light-distinct.DESIGN.md | node ../UI-Spec/record-design-lint.mjs light-distinct
npm exec --yes --package=@google/design.md@0.4.0 -- designmd lint ../UI-Spec/themes/dark-distinct.DESIGN.md | node ../UI-Spec/record-design-lint.mjs dark-distinct
npm exec --yes --package=@google/design.md@0.4.0 -- designmd lint ../UI-Spec/themes/light-standard-compact.DESIGN.md | node ../UI-Spec/record-design-lint.mjs light-standard-compact
npm exec --yes --package=@google/design.md@0.4.0 -- designmd lint ../UI-Spec/themes/dark-standard-compact.DESIGN.md | node ../UI-Spec/record-design-lint.mjs dark-standard-compact
npm exec --yes --package=@google/design.md@0.4.0 -- designmd lint ../UI-Spec/themes/light-distinct-compact.DESIGN.md | node ../UI-Spec/record-design-lint.mjs light-distinct-compact
npm exec --yes --package=@google/design.md@0.4.0 -- designmd lint ../UI-Spec/themes/dark-distinct-compact.DESIGN.md | node ../UI-Spec/record-design-lint.mjs dark-distinct-compact
```

The unit check binds each report to its exact palette DESIGN.md SHA-256. After editing tokens or design prose, regenerate DESIGN.md, rerun the official check and review any changed findings. The expected warning set is explicit in the unit test, so new findings require review rather than being silently treated as the same result.

Catalog visual review covered light buttons/fields, paired originals and pointer comparison, gallery media, optional aura, dark/compact controls/fields/radial progress/phone frame, a native tooltip and mobile controls. The complete class/markup audit caught duplicate control IDs, a nonshrinking grid track, native figure margins, a shorthand serialization conflict and selector specificity in gallery/motion states; regression checks cover the corrected outcomes. Existing rule objects were compared with the preceding revision and remain identical.

See [REVIEW.md](REVIEW.md) for remaining manual review, the acceptance gates and mandatory rework when a maintainer rejects a purpose or user intent.
