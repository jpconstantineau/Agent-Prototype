# Sources and project decisions

Reviewed 2026-10-29. The guidance below is adapted into project-specific choices, not a claim of endorsement or a single official Google UI system.

| Primary source | What informs this specification | Project decision / limit |
| --- | --- | --- |
| [Google Labs DESIGN.md format](https://github.com/google-labs-code/design.md/blob/main/docs/spec.md) and [repository](https://github.com/google-labs-code/design.md) | Exact tokens plus human rationale, alpha format, ordered design sections | Generated DESIGN.md uses its published schema and canonical sections. The CSS decision ledger is a project extension in separate files, not an invented required DESIGN.md field. |
| [Google Modern Web Guidance](https://developer.chrome.com/docs/modern-web-guidance) | Agent-oriented, current browser implementation guidance | Prefer native capabilities and test browser behavior. This is not a prescribed Google color/spacing palette. |
| [web.dev responsive design](https://web.dev/learn/design) | Content-driven responsive layouts and user input diversity | Fluid layouts, two demonstrated breakpoints, no device sniffing. Bootstrap thresholds are a project/framework choice. |
| [web.dev form design](https://web.dev/learn/forms/design-basics) and [accessible forms](https://web.dev/learn/forms/accessibility) | Clear labels, structure and input support | Labels persist while editing; required constraints and help are explicit. |
| [web.dev keyboard focus](https://web.dev/learn/accessibility/focus) | Native focusable controls and logical focus order | Use native summary/button/link behavior and explicit focus return, not positive tabindex. |
| [Bootstrap 5.3 grid](https://getbootstrap.com/docs/5.3/layout/grid/) and [5.3.8 distribution](https://getbootstrap.com/docs/5.3/getting-started/download/) | Twelve-column responsive flex grid and gutters | Literal selected grid declarations plus authored project components; full bundle and plugins are not shipped. Exact provenance is checked locally. |
| [Bootstrap CSS custom properties](https://getbootstrap.com/docs/5.3/customize/css-variables/) and [forms](https://getbootstrap.com/docs/5.3/forms/overview/) | Framework customization and conventional component vocabulary | Semantic ui- tokens; only the documented subset of Bootstrap class names exists. |
| [Jakob Nielsen’s usability heuristics, NN/G](https://www.nngroup.com/articles/ten-usability-heuristics/) | Observable state, explicit escape, recognition and recoverable errors | Saved/draft separation, persistent Edit cue and Cancel. These are heuristics to challenge, not user research proving this particular pattern. |
| [GOV.UK question design](https://www.gov.uk/service-manual/design/designing-good-questions) | Asking only for information with an actual service purpose | Each field needs a domain purpose; optional data stays optional. |
| [WHATWG details and summary](https://html.spec.whatwg.org/multipage/interactive-elements.html#the-details-element) | Native disclosure semantics and open state | Use native click-to-edit disclosures, with a small explicit save/cancel enhancement. |
| [WCAG 2.2 reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html), [contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html), [target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) and [text spacing](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html) | Measurable accessibility constraints and exceptions | 4.5:1 text, 3:1 meaningful boundaries, 320px reflow except bounded two-dimensional tables, user spacing support; project chooses 44px targets rather than claiming WCAG requires them. |

The green identity is adapted from the existing Daylist theme. The exact revised neutral, error, focus and state roles are project proposals checked against the permitted contrast matrix. The 4px-based scale, 65ch prose cap, 75rem container cap, 44px comfort targets, no-motion baseline and explicit Save/Cancel behavior are deliberate project choices with ledger rationale. They are not attributed to an official Google visual specification.

Only original explanations and short necessary API/token examples are included. Upstream Bootstrap code is retained under its MIT license. `bootstrap-provenance.json` records the source URL, full upstream CSS SHA-256 and the declarations selected; `verify-bootstrap.mjs` can recheck that version without changing deployed files.
