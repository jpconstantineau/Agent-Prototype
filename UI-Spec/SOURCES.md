# Sources and project decisions

Reviewed 2026-10-29. The guidance below is adapted into project-specific choices, not a claim of endorsement or a single official Google UI system.

| Primary source | What informs this specification | Project decision / limit |
| --- | --- | --- |
| [shadcn/ui core catalog](https://ui.shadcn.com/docs/components) and [button composition](https://ui.shadcn.com/docs/components/base/button) | Core component concepts and original React dependency boundary | Independently authored HTML/CSS equivalents, with explicit native alternatives and script-dependent exclusions. No source bundle is imported. |
| [daisyUI core catalog](https://daisyui.com/components/), [usage](https://daisyui.com/docs/use/), [modal methods](https://daisyui.com/components/modal/) and [OTP](https://daisyui.com/components/otp/) | CSS-component inventory and limits between presentation and behavior | Dated 5.7.50 catalog mapping; original classes reuse the existing project colors/density, not upstream themes or hidden-checkbox modals. |
| [Chrome command/commandfor](https://developer.chrome.com/blog/command-and-commandfor) and [interest invokers](https://developer.chrome.com/docs/modern-web-guidance/guides/ui-behaviors/interest-triggered-action-previews) | Browser-owned declarative dialogs and hover/focus support | Native target Chrome, explicit click route and documented feature requirements; no component script/polyfill. |
| [W3C tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/) and [tooltip pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/) | Keyboard/state contracts beyond visual resemblance | Native radio/link alternatives never pretend to implement ARIA tabs or application menus; tooltip uses native interest/Escape. |
| [Charts.css](https://chartscss.org/components/data/), [Carbon](https://www.carbondesignsystem.com/building-blocks/data-visualization/simple-charts), [Tremor](https://www.tremor.so/docs/visualizations/spark-chart), [Mantine](https://mantine.dev/core/ring-progress/) and [Adobe Spectrum](https://spectrum.adobe.com/web/rsp/components/meter) | Dashboard pattern research, reviewed 30 October 2026 | Original native/CSS subset, separately documented in DASHBOARDS.md; no imported chart implementation or implication that all upstream charts are CSS-only. |

| [Google Modern Web Guidance](https://developer.chrome.com/docs/modern-web-guidance) | Agent-oriented, current browser implementation guidance | Prefer native capabilities and test browser behavior. This is not a prescribed Google color/spacing palette. |
| [web.dev responsive design](https://web.dev/learn/design) | Content-driven responsive layouts and user input diversity | Fluid layouts, two demonstrated breakpoints, no device sniffing. Bootstrap thresholds are a project/framework choice. |
| [web.dev form design](https://web.dev/learn/forms/design-basics) and [accessible forms](https://web.dev/learn/forms/accessibility) | Clear labels, structure and input support | Labels persist while editing; required constraints and help are explicit. |

Exact provenance is checked locally. |
| [Bootstrap CSS custom properties](https://getbootstrap.com/docs/5.3/customize/css-variables/) and [forms](https://getbootstrap.com/docs/5.3/forms/overview/) | Framework customization and conventional component vocabulary | Semantic ui- tokens; only the documented subset of Bootstrap class names exists. |
| [Jakob Nielsen’s usability heuristics, NN/G](https://www.nngroup.com/articles/ten-usability-heuristics/) | Observable state, explicit escape, recognition and recoverable errors | Saved/draft separation, persistent field labels, native focus feedback and Cancel. These are heuristics to challenge, not user research proving this particular pattern. |
| [GOV.UK question design](https://www.gov.uk/service-manual/design/designing-good-questions) | Asking only for information with an actual service purpose | Each field needs a domain purpose; optional data stays optional. |
| [WCAG use of color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html) and [APG switch pattern](https://www.w3.org/WAI/ARIA/apg/patterns/switch/) | Meaning beyond hue; stable named native binary preferences | Four palettes all retain text/native state; alternate status borders add line patterns. Native checkbox-based sliders expose role=switch and checked, without a changing label. |
| [Bootstrap color modes](https://getbootstrap.com/docs/5.3/customize/color-modes/) | Global data-bs-theme palette governance | Full light/dark role overrides with a separate data-vision preference; no inversion or component-specific hard-coded modes. |
| [ISA-101 series catalog](https://www.isa.org/standards-and-publications/isa-standards/isa-101-standards) | Current ISA listing: ISA-101.01-2015, ISA-TR101.01-2022 HMI Philosophy and ISA-TR101.02-2019 HMI Usability and Performance | A lifecycle and usability framework, not a source of mandatory web color hex values. This reference adopts a documented design philosophy; it does not claim industrial HMI conformance. |
| [ISA InTech: How DCS Migration Improves Operator Experience](https://www.isa.org/intech-home/2023/april-2023/features/how-dcs-migration-improves-operator-experience) | Gray backgrounds and sparse meaningful color as part of high-performance HMI practice; content hierarchy also matters | Achromatic page/panel/secondary fills in all appearances, neutral guidance and status fills, compact action/focus/state color. Exact values and dark adaptation are project choices in HMI-PHILOSOPHY.md. |
| [Chrome vision-deficiency emulation](https://chromedevtools.github.io/devtools-protocol/tot/Emulation/#method-setEmulatedVisionDeficiency) | Visual inspection under common simulated deficiencies | Browser checks exercise protanopia, deuteranopia, tritanopia and achromatopsia. Simulation is not a claim of universal usability or clinical equivalence. |
| [WHATWG details and summary](https://html.spec.whatwg.org/multipage/interactive-elements.html#the-details-element) | Native disclosure semantics and open state | Use native disclosures only for optional support; prefilled native inputs implement the corrected inline-edit requirement. |
| [W3C headings](https://www.w3.org/WAI/tutorials/page-structure/headings/) and [content structure](https://www.w3.org/WAI/tutorials/page-structure/content/) | Meaningful heading rank, lists, quotations and figures | Scoped document layer with six explicit sizes, native markers/semantics and documented margin owners. Exact typography values are project choices. |
| [WHATWG grouping content](https://html.spec.whatwg.org/multipage/grouping-content.html) and [text semantics](https://html.spec.whatwg.org/multipage/text-level-semantics.html) | Native meanings of lists, pre, figure, emphasis, quotation, keys, output and annotations | Preserve native semantics; record inherited behavior where extra CSS has no concrete purpose. Styles do not expand the Markdown renderer allowlist. |
| [W3C CSS box model and margin collapse](https://www.w3.org/TR/CSS22/box.html#collapsing-margins) | Distinct roles of margin, padding, border and content; block-margin collapse | One gap owner per context; field/stack grids use explicit gaps and child resets. Normal/compact values are project choices, not CSS requirements. |
| [W3C Media Queries: any-pointer](https://www.w3.org/TR/mediaqueries-4/#any-input) | A hybrid device can have both coarse and fine inputs | Compact restores the 2.75rem target floor if any pointer is coarse or there is no pointer; content spacing can remain compact. |
| [WCAG 2.2 reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html), [contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html), [target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) and [text spacing](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html) | Measurable accessibility constraints and exceptions | 4.5:1 text, 3:1 meaningful boundaries, 320px reflow except bounded two-dimensional tables, user spacing support; project chooses 44px normal/coarse-pointer targets and a 36px fine-pointer compact floor, rather than claiming WCAG requires them. |

The maintainer selected azure #006aa8 in both modes and accepted written-label primary buttons without a permanent outline. This supersedes the inherited green action identity. Related blue text/native accent roles are independently checked for contrast; no secondary/tertiary color-wheel scheme is implied. [W3C's boundary explanation](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html#boundaries) informs the narrow exception documented in COLOR-SELECTION.md; label and focus requirements remain enforced. The achromatic structural palette responds to maintainer feedback using ISA-published principles; the exact neutral, error, focus and state roles are project decisions checked against the permitted contrast matrix. No glare, fatigue or operator-performance improvement is claimed from the colors alone. The normal 4px-based scale, explicit compact 2px rhythm, 65ch prose cap, 75rem container cap, 36/44px comfort targets, protected 1px boundaries and focus geometry, no-motion baseline and explicit Save/Cancel behavior are deliberate project choices with ledger rationale. They are not attributed to an official Google visual specification.

Only original explanations and short necessary API/token examples are included. Upstream Bootstrap code is retained under its MIT license. `bootstrap-provenance.json` records the source URL, full upstream CSS SHA-256 and the declarations selected; `verify-bootstrap.mjs` can recheck that version without changing deployed files.
