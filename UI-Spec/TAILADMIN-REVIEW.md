# TailAdmin UI Elements review

## Purpose

Compare the requested TailAdmin inventory and its linked HTML examples with this project’s components. Record each gap, use case, decision and implementation boundary. This is a pattern review with original project code, not an adoption of Tailwind, TailAdmin packages, templates, assets or colors. Reviewed 2026-10-30.

## User intent

Find a component by the job it supports, see a realistic composition and understand which native interactions are available. Read identity, state, metadata, work progress and page-wide information without confusing their purposes.

## Agent intent

Implementation agents use the mapped component HTML and audited CSS rather than copying a visually similar upstream widget. Runtime agents do not act through this spec; no tool, approval, cookie consent, data persistence or network permission is granted by presentation.

## Adoption and behavioral boundaries

Existing maintainer decisions take precedence: muted neutral structural surfaces, selected azure, four palettes, normal/compact spacing, protected focus/targets, native folder radios and border-only alert dialogs. The review adds useful compositions within those decisions. Arbitrary opacity links, status colors applied decoratively, auto-rotating content and fixed overlays do not improve their stated purposes here.

An alert describes a condition near its recovery action; a notification reports a settled item/event; an announcement applies to the whole current surface. A record ribbon highlights version/category metadata. A badge annotates an owner with supplemental information, while an aligned status indicator describes its state. Use actual observed data for all of these words. CSS does not determine urgency, mark notifications read, persist dismissals or schedule updates.

Dropdown navigation remains native popover plus real links. A choice of values uses select/radio; an application command needs a real button and authorized dispatch. A native method=dialog form can validate a local draft and return a browser-owned result, but that result is not a committed application receipt or an approval to execute tools. Actual confirmation and saved-state handling remain covered by the app specs.

Media use local fixtures only. The 480×270 WebM is an original silent two-second moving-block test clip; its VTT track and adjacent transcript describe the same movement. Native video controls own playback, seeking, captions and fullscreen. The video stays paused initially, uses preload=none, contains the full frame at every demonstrated ratio and has a governed outer focus perimeter. Native control internals remain browser/OS behavior, not authored CSS. External embeds need their own consent, source/permission and CSP decision.

Image grids preserve intrinsic dimensions and complete meaningful artwork; captions explain purpose. Object-fit:cover is confined to the optional identity thumbnail, with the person’s written name retained. No onerror script or CSS attempt to detect a failed download is implied; runtime image failure handling must provide a truthful fallback.

## CSS rationale and verification

All properties, including local image/media size, avatar sizes, card columns, semantic edges, focus overrides and list clearance, appear in CSS-DECISIONS.md and BOX-MODEL-AUDIT.md. New rules use catalog- IDs and the existing catalog verification family. The canonical HTML is generated in COMPONENT-CATALOG.md and the live catalog. Normal/compact spacing uses governed tokens; readability, focus and native target floors remain protected.

The quiet badge’s success/warning text on the neutral surface adds explicit 4.5:1 contrast requirements. Filled-alert links inherit contrasting ink and use a 3px outline with a 3px offset on their filled surface; forced colors restores the platform focus role. Generic controls continue to use the original neutral-plane focus contract.
